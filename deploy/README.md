# 実機で動かす:三足から

学習した方策を、unitree_sdk2 の低レベル制御で Go2 に載せるためのプログラムです。方策は、`scripts/export_onnx.py` で書き出した `policy.onnx` と `deploy.json` です。

| ファイル | 役割 |
|---|---|
| `go2_real.py` | 実機用の制御プログラム。実機と、下のシミュレーターの両方で、まったく同じコードが動く |
| `policy.py` | センサーの値 → 観測 → ONNX → 目標の関節角。観測は、5ステップの履歴・歩容の時計・歩き方の one-hot |
| `remote.py` | リモコンの読み取り:`LowState.wireless_remote` |
| `sim_dds.py` | 実機と同じ通信で動く MuJoCo。通信は DDS の `rt/lowstate` / `rt/lowcmd`。リモコンの操作も台本どおりに送る |
| `run_sim_test.sh` | `sim_dds.py` と `go2_real.py` をつないで、通しで試す |
| `sim2sim_mujoco.py` | 通信なしで方策を直接 MuJoCo で動かす。学習後の確認用 |

Python は `~/go2_sim2real/.venv/bin/python` を使います。unitree_sdk2py・mujoco・onnxruntime が入っています。

## 1. 書き出し

```bash
R=logs/rsl_rl/unitree_go2_tripodcool/2026-10-28_22-09-13_tripodcool_c2
~/go2_sim2real/.venv_isaac/bin/python scripts/export_onnx.py $R/model_11299.pt --tripod walk --out $R/exported_real
```

三足では、`deploy.json` に両方の歩き方、けんけんと3拍子の歩きが入ります。歩き方は、実機で立っているときに X / Y で選びます。

## 2. 実機と同じ通信のシミュレーターで確かめる

```bash
deploy/run_sim_test.sh $R/exported_real $R/deploy_test/tripod --scenario tripod --unitree_curve
```

シミュレーターは DDS のドメイン 1 で、ループバックで動きます。実機はドメイン 0 なので、シミュレーター用に起動した制御プログラムが実機に指令を送ることはありません。

## 3. ネットワーク

Go2 は `192.168.123.0/24` で動きます。PC 側には `192.168.123.99/24` を固定で割り当てます。試験そのものにインターネットは要りません。方策・SDK・Python はすべて PC の中にあります。

**有線 LAN の口が `eno1` の1つだけのとき:** インターネットのケーブルを抜いて Go2 のケーブルを挿し、Go2 用の設定に切り替えます。その間はインターネットに接続できません。

```bash
# 最初の1回だけ(インターネットにつながっているうちに作っておく。自動では有効にしない)
nmcli con add type ethernet ifname eno1 con-name go2 ipv4.method manual ipv4.addresses 192.168.123.99/24 ipv6.method disabled connection.autoconnect no
# Go2 のケーブルに挿し替えたら
nmcli con up go2
ping -c 3 192.168.123.161
# 終わってインターネットのケーブルに戻したら
nmcli con up "Wired connection 1"
```

**USB の LAN アダプタを足したとき:** 上の `eno1` をアダプタの名前に替えて、`connection.autoconnect no` を外します。アダプタの名前は `ip -br link` で確かめます。

まず読み取りだけで確かめます。何も送らないので、組み込みの制御のままです。画面の案内に従うだけで、結果は `deploy/real_logs/monitor_<日時>.npz` と `.json` に残ります。

```bash
~/go2_sim2real/.venv/bin/python deploy/monitor.py --iface eno1
```

- 5 秒間、届く頻度、関節の角度、胴体の傾き、モーターの温度を記録します。届く頻度は 500 回/秒前後です。
- リモコンはここでは試しません。組み込みの制御が動いている間にボタンを押すと、組み込みの動きが出るためです。

## 4. 実機で動かす

**始める前**
- バッテリーは十分ですか。周りの 2 m に人や物がありませんか。リモコンの電源は入っていますか。
- ロボットは床に伏せた状態ですか。最初は、人が胴体のひも、ハーネスを持てるとよいです。
- モーターは冷えていますか。

```bash
R=logs/rsl_rl/unitree_go2_tripodcool/2026-10-28_22-09-13_tripodcool_c2
~/go2_sim2real/.venv/bin/python deploy/go2_real.py --mode real --iface eno1 --export_dir $R/exported_real --max_fwd 0 --max_back 0 --max_vy 0 --max_wz 0
```

| # | 操作 | 画面・ロボット |
|---|---|---|
| 1 | `yes` と入力 | 組み込みの制御が伏せてから止まり、ロボットは脱力する。`ready` と出る |
| 1b | **select** | `[OK] select(非常停止)が読めました`。これを確かめるまで start は効かない |
| 2 | **start** | 3 秒かけて四足で立つ。`STAND -> HOLD` |
| 3 | けんけんは **X**、歩きは **Y** | `gait -> hop` / `gait -> walk`。立っている間だけ選べる |
| 4 | **A** | `HOLD -> POLICY`。方策が右前足を上げる |
| 5 | 左スティック前後・左右、右スティック左右 | 前後・横・旋回。倒し切りの速さは起動時に決める:前 `--max_fwd`・後ろ `--max_back`・横 `--max_vy`・旋回 `--max_wz`。上のコマンドはすべて 0 なので、**倒しても動かない**。スティックが読めていることは画面の `sticks` で分かる |
| 6 | **B** | 上げた足をたたんで肩の下に下ろし、一度伏せてから立ち直す。約 8 秒かかる。足の位置が最初と同じになる。終わるまで A は押さない |
| 7 | **select** | 脱力して伏せる。**危ないと感じたら select**。伏せて止まったあと start で立ち直せる |
| 8 | Ctrl-C | `deploy/real_logs/` に、記録の `.npz` と画面の出力の `.txt` を保存 |

**自動で止まる条件**
- 脱力する:通信が 0.1 秒以上途絶えたときです。方策の実行中に、胴体が 50° 以上傾いたときと、関節が可動域から 0.1 rad 以上外れたときも脱力します。
- 四足に戻る、B と同じ動き:どれかのモーターが 70 °C 以上になったときです。この値は `--temp_stop` で変えられます。冷えるまで A は受け付けません。60 °C で警告を出します。
- Unitree 自身の保護の温度はまだ分かっていません。最初の試験で温度の上がり方を記録して、決め直します。

**速さの指令について**
- 倒し具合 × 倒し切りの速さ が指令になります。例えば、`--max_fwd 0.15` で7割倒すと 0.105 m/s です。
- 学習では、各方向で **0.1 未満の指令は「止まれ」** として扱いました。倒し切りの速さを 0.1 以下にすると、どれだけ倒しても動きません。
- 何も付けずに起動したときの倒し切りの速さは、前 0.3、後ろ 0.2、横 0.15 m/s、旋回 0.5 rad/s です。シミュレーターで確かめた値です。学習の範囲は、前 0.5、後ろ 0.3、横 0.2 m/s、旋回 0.6 rad/s までです。

**勧める順番**
1. 指令なし、上のコマンドのまま:start → A → 10 秒立つ → B → select の順に進めます。
2. けんけんで、少しだけ動かします。立ったあと A の前に **X** を押します。前進は7割以上、旋回は3割以上倒したときだけ効きます。
   ```bash
   ~/go2_sim2real/.venv/bin/python deploy/go2_real.py --mode real --iface eno1 --export_dir $R/exported_real --max_fwd 0.15 --max_back 0 --max_vy 0 --max_wz 0.3
   ```
3. 問題なければ、何も付けずに起動して、けんけんで前後・旋回を試します。前 0.3、旋回 0.5 までです。
4. 歩きは Y で選びます。シミュレーターでは、実測の関節の摩擦を入れると旋回の途中で倒れることがあったので、最後に、前進だけから試します。カバンは、方策を動かしてから人が前腕に掛けます。

## 5. シミュレーターでの確認結果:TripodCool c2、2026-10-30

`run_sim_test.sh` で、けんけん → B → 歩き → B → select を通しで試しました。倒し切りの指令は、前 0.3、後ろ 0.2、横 0.15 m/s、旋回 0.5 rad/s です。

| 条件 | 転倒 | けんけん 前 / 旋回 / 後ろ | 歩き 前 / 旋回 / 後ろ |
|---|---|---|---|
| そのまま | なし | 0.19 / 0.39 / −0.12 | 0.17 / 0.32 / −0.06 |
| トルクと速さの曲線 | なし | 0.19 / 0.39 / −0.12 | 0.18 / 0.32 / −0.05 |
| 曲線+カバン 2 kg、歩きのとき | なし | 0.19 / 0.39 / −0.13 | 0.16 / 0.35 / −0.09 |
| 実測の関節 `--real_joints`、曲線やカバンの有無を含む | 歩きで 6 回中 3 回倒れた。けんけんは 0 回 | 0.09 / 0.22〜0.23 / −0.04〜−0.06 | 0.03〜0.06 / 0.16 / −0.04〜−0.05 |

- 通信なしの `sim2sim_mujoco.py` とほぼ同じ速さが出ます。観測の作り方と関節の並びは、学習と合っています。
- 実測の関節の摩擦を入れると、けんけんは倒れずに遅くなるだけです。歩きは、同じ条件でも倒れたり倒れなかったりします。倒れるのは、右前足を上げる瞬間や、旋回の途中です。**実機では、けんけんから試します。**
- 推論は 1 ms 未満、制御の周期の遅れは 0 回でした。

## 6. 実機の1回目:2026-10-30

- 通信は 500 回/秒、制御の周期の遅れは 0 回、推論は 0.5 ms でした。select・スティックも正しく読めました。
- 歩き、指令なしで A:右前足を上げた三足立ちが 33 秒安定しました。Y を押さなかったので、既定の walk です。傾きは 9° で、学習の目標の頭上げ 10° と同じです。温度は 2〜3 °C 上がっただけでした。
- **B → もう一度 A で 0.4 秒で崩れ、関節の可動域の安全装置が脱力させました。** B で右前足が既定より前に着地し、ほかの脚の足の位置も三足のときのまま残っていました。太もものずれは 0.2〜0.3 rad でした。MuJoCo でもその姿勢から始めると 4 回中 4 回倒れ、既定の姿勢からなら倒れませんでした。
  - 直したこと:B では上げた脚をたたんでから下ろし、一度伏せて立ち直します。足の位置が最初の立ち上がりと同じになります。A は、既定の姿勢から 0.2 rad 以上ずれていたら受け付けません。シミュレーターで A・B を 4 回繰り返して倒れないことを確かめました。
- `eno1: does not match an available interface`:`eno1` が Go2 のネットワークに切り替わっていないときに出ます。`nmcli con up go2` をやり直します。制御プログラムも起動時に確かめて、日本語で知らせます。
